# Ostinato

A mobile-first music production app (DAW) for iPhone, iPad, Android, Windows, macOS and Linux,
built from one C++ codebase with [JUCE 9](https://juce.com). Write drum patterns, play and record
instruments, arrange a song, record vocals, mix with effects and automation, and export a finished
track. Everything below is real audio processing, not a mock-up.

## Studio Synth

A synth for designing sounds from scratch, in six tabs:

- **Oscillators**: three oscillators, each sine, saw, square, triangle, pulse (with width), noise,
  supersaw or any of 5 morphing wavetables (with position); octave, semitone, fine, level, pan, up to
  8 unison voices with detune and stereo spread, free or reset phase. FM of osc 1 by osc 2, hard sync
  of osc 2 to osc 1, ring modulation, a sub oscillator (1 or 2 octaves down, 3 shapes) and coloured noise.
- **Filters**: two filters, each low-pass 12/24, high-pass 12/24, band-pass, notch, peak, comb (tuned,
  for plucks and metallic tones) or formant (vowels); cutoff, resonance, drive, key tracking, envelope 2
  amount, velocity. Serial or parallel. The tab draws the filter curves.
- **Envelopes**: amp envelope plus two free envelopes (drawn live).
- **LFOs**: three, each sine/triangle/saw/square/sample & hold/smooth random, free or tempo-synced,
  per note (restarts) or shared (free running), with delay and fade-in.
- **Mod Matrix**: 8 slots. Sources: envelopes 2 and 3, the amp envelope, LFOs 1-3, velocity, key,
  mod wheel, pitch bend, per-note random, 4 macros. 26 destinations: pitch (all or per oscillator),
  levels, wavetable positions, pulse width, FM, ring, unison detune, sub, noise, both filters' cutoff and
  resonance, drive, pan, volume, LFO rates.
- **Macros & Voice**: 4 macro knobs (automatable, MIDI-learnable), 1-16 voices, poly / mono / legato,
  glide, bend range, transpose, velocity, level and the Shape section.

12 factory sounds show what it does (supersaw lead, reese bass, sub bass, evolving pad, FM bell, sync
lead, pluck, wobble bass, acid bass, talking formant, comb pluck, brass stab). Randomize makes a new
playable sound; Mutate nudges the current one.

## Effect Designer

Six module slots in series. Each slot is one of: low-pass, high-pass, band-pass, notch, peak EQ, drive,
wavefolder, bitcrusher, delay, chorus, ring modulator, comb filter, gain & pan (with width), small reverb
or tremolo, with three knobs that are renamed for the module (e.g. Delay: Time / Feedback / Tone) and a
mix. Two LFOs and an envelope follower can move any knob through 4 modulation slots (that is how the
Auto-Wah preset works). Input, output and dry/wet. Save a design to "My effects" and add it on any track.

## Hearing yourself while recording

No software can play your voice back with literally zero delay: sound has to pass through the audio
interface's buffers on the way in and out. So the booth offers three choices:

- **Off**: you hear the song but not the microphone.
- **Direct (interface)**: the app stays silent for that track and your audio interface sends the mic
  straight to your headphones with zero delay (turn on its direct-monitor switch). You hear your voice
  dry, without the app's effects.
- **Through effects**: you hear your voice through the live chain (compressor, EQ, reverb...). The delay
  is shown on screen. **Low latency mode** switches the device to its smallest buffer; on a typical USB
  interface or iPhone that is a few milliseconds, which most singers can't notice.

Whatever you hear, you choose separately whether the take is recorded **clean** (add the effects later and
change them any time) or **with effects** (a stereo file with the chain printed in).

## Build it

You need CMake 3.22+. The first configure downloads JUCE 9.0.5 automatically
(or pass `-DJUCE_DIR=/path/to/JUCE`).

**Windows (PC), easiest:** install Visual Studio Community (2022 or newer) with "Desktop development with C++",
then double-click `build-windows.bat`. It produces `Ostinato.exe` next to it (first build takes 5-15 minutes).

**Windows (PC), manual.** Install [Visual Studio 2022](https://visualstudio.microsoft.com/) with the
"Desktop development with C++" workload (it includes CMake). Then, in a Developer PowerShell:

```
cmake -B build -A x64
cmake --build build --config Release
build\Ostinato_artefacts\Release\Ostinato.exe
```

**iPhone / iPad.** Needs a Mac with Xcode 15+ and a (free) Apple ID.

```
cmake -B build-ios -G Xcode -DCMAKE_SYSTEM_NAME=iOS -DCMAKE_OSX_DEPLOYMENT_TARGET=15.0
open build-ios/Ostinato.xcodeproj
```

In Xcode select the Ostinato target, Signing & Capabilities, choose your team, plug in the iPhone
and press Run. Songs, exports and imports appear in the Files app under On My iPhone > Ostinato.

**Install on iPhone without a Mac.** Push this folder to GitHub; the workflow's iOS job uploads
`Ostinato-unsigned.ipa`. Sign and install it from Windows with [Sideloadly](https://sideloadly.io) or
AltStore using your Apple ID. With a free Apple ID the app must be re-signed every 7 days; a paid
Apple Developer account ($99/year) lasts a year and allows TestFlight / App Store.

**macOS.** `cmake -B build -G Xcode && cmake --build build --config Release`

**Android.** Use JUCE's Projucer/Android Studio route or `juce_add_gui_app` with the Android
toolchain; the code has no platform-specific Android parts.

**Linux.** Install the JUCE Linux dependencies (ALSA, FreeType, X11 dev packages; see
`.github/workflows/build.yml`), then `cmake -B build -DCMAKE_BUILD_TYPE=Release && cmake --build build -j`.

**Without a Windows PC or Mac:** push this folder to a GitHub repository. The included
workflow builds and tests Windows, macOS, iOS (unsigned) and Linux, and attaches the Windows
`.exe` and macOS app as downloads.

## Tests

```
Ostinato --selftest report.txt     # 238 checks; renders real audio and measures it
Ostinato --uitest out_dir          # drives the real window with taps, drags, long-presses, menus
Ostinato --screenshots out_dir     # every screen at phone, landscape and desktop size
```

The self-test checks, among other things: every preset sounds and is in tune; notes start on the
exact sample (including across tempo changes); drum swing, probability and ratchets; each effect does
what it claims (limiter never exceeds its ceiling, a 250 ms delay echoes at 250.02 ms, +12 st pitch
shift doubles frequency...); mixer gain, pan, solo, phase, buses and sends; automation follows the
timeline; audio clip placement, sample-rate conversion, pitch-preserving stretch, fades, normalize,
loop, trim, reverse; exports contain the whole song plus tails; project files round-trip exactly;
MIDI files round-trip; key and tempo detection; real-time recording; performance. Also: every Studio
Synth preset in tune, unison width, both filters, envelope sweeps, LFO vibrato through the mod matrix,
macros, FM, sync, ring mod, sub, comb tuning, voice limits, 60 random patches all safe; the Shape section
on several engines; drum pad attack/start/pitch drop/low cut/drive; the de-esser; all 15 Effect Designer
modules, its delay timing, LFO and envelope-follower modulation; and the booth (monitor off / direct /
through effects, input gain, record clean vs with effects, chain latency, saving, old-file migration).

## How it is put together

```
Source/
  Core/      Project model + JSON format, project storage, session (undo, autosave), theory, MIDI files, settings
  Engine/    DSP primitives, instruments, effects, samples + drum synthesis, compiler/renderer, real-time engine, exporter
  UI/        Design system, widgets (knobs, faders, meters, keyboard), main window, 11 screens
  Platform/  Apple-only code (AAC encoder, haptics)
  Tests/     Self-test and UI test
```

The message thread owns the project. Every edit compiles an immutable snapshot (sorted note events,
clip descriptors, automation, routing order) that is handed to the audio thread with a lock-free
pointer swap; the audio thread never allocates, locks or frees, and old snapshots are deleted back
on the message thread. Knob values travel through atomic parameter sets, so turning a knob never
rebuilds anything. Playback and export run the same renderer, so the export sounds exactly like what
you heard. Rendering happens in 64-sample sub-blocks with sample-accurate note timing; when playback
stops and the output has been silent for 2 seconds the engine idles to save battery.

## Not finished / not verified

- **MP3 export** is not included: there is no MP3 encoder that can ship inside an App Store app
  without licensing problems. WAV, FLAC, OGG and (on Apple) AAC are available.
- **Not compiled here:** this was built and tested on Linux. The Windows, macOS and iOS builds use the
  same code, but the Apple-only file (`Source/Platform/Apple.mm`: AAC encoding, haptics) and the
  Windows/MSVC build were not compiled. The GitHub workflow builds both.
- **Real audio hardware** was not available on the build machine: playback and recording were tested
  through the engine's fallback clock with a simulated input. Device selection, latency and
  interruptions (phone calls) rely on JUCE's CoreAudio/WASAPI/ASIO/Oboe drivers.
- **Multi-touch pinch** is implemented, but Linux test builds have no multi-touch, so zoom was tested
  through the trackpad magnify path. Try it on a phone.
- Low latency mode and the booth were tested with the simulated input on the build machine, not with a
  real microphone; the achievable delay depends on your device and its driver.
- Studio Synth envelopes have a fixed curve shape (linear attack, exponential decay/release); shared
  (free-running) LFOs ignore the matrix's "LFO rate" destinations, per-note LFOs follow them.
- Mid-song time-signature changes are supported by the engine and file format, but the UI only edits
  the song's main time signature. Tempo changes have full UI.
- MIDI clock is follow-only (no clock output). No AU/VST plug-in hosting.
- Samples go to drum pads and the sampler through a menu, not drag-and-drop between screens
  (drag-and-drop works from the palette strip into the Song view).
